## 📌 درباره پروژه

یک نرم‌افزار منبع‌باز و مبتنی بر پایتون که جهت عبور از سیستم‌های پیچیده فیلترینگ طراحی شده است. 

این ابزار به‌جای تکیه بر یک پروکسی واحد، ابتدا وضعیت دقیق شبکه کاربر را در چندین لایه آنالیز کرده و سپس با استفاده از یک الگوریتم هوشمند، بهترین روش دور زدن را انتخاب و اعمال می‌کند. همچنین یک داشبورد تحت وب نیز برای پایش لحظه‌ای فراهم می‌سازد.

## ✨ ویژگی‌های شاخص

### ۱. تحلیلگر عمیق شبکه (Deep Network Profiler)
- **بررسی لایه IP:** تشخیص قطعی کامل، قطعی اینترنت بین‌الملل (National-Only) و وضعیت ICMP/TCP Ping.
- **بررسی لایه DNS:** تشخیص DNS Hijacking، بررسی وضعیت DNS over HTTPS (DoH) و مسدودی پورت 53 (UDP DNS).
- **تشخیص DPI:** آنالیز رفتار سیستم فیلترینگ از طریق بررسی SNI (YouTube/Google) و تشخیص RST تزریقی (SNI Filtering).
- **بررسی پورت‌ها و UDP:** اسکن پورت‌های متداول VPN و بررسی وضعیت ترافیک UDP و QUIC.
- **سنجش پهنای باند:** تشخیص Throttling شدید (کاهش دستی سرعت بین‌الملل) در مقایسه با سرعت اینترنت داخلی.

### ۲. تکنیک‌های دور زدن خلاقانه و پیشرفته
- **Proxy Chaining (زنجیره‌سازی پروکسی):** در زمان DPI تهاجمی، پروتکل داخلی داخل ShadowTLS یا VLESS-Reality کپسوله می‌شود تا امضای ترافیک کاملاً پنهان بماند.
- **WARP over Reality:** کپسوله کردن ترافیک WireGuard (Cloudflare WARP) داخل تونل VLESS-Reality برای دور زدن مسدودسازی IPهای WARP.
- **اسکنر IP تمیز (Clean IP Scanner):** جستجوی خودکار IPهای سالم Cloudflare/Gcore/AWS برای اتصال به Cloudflare Workers.
- **فرگمنتیشن داینامیک (Dynamic Fragmentation):** تغییر خودکار اندازه fragment بسته‌های TLS بر اساس شدت DPI سیستم فیلترینگ.
- **Balancer و Observatory:** توزیع بار روی چندین کانفیگ به صورت همزمان با استفاده از قابلیت‌های داخلی Xray.

### ۳. اتوماسیون و مدیریت کانفیگ
- دریافت خودکار ساب‌اسکریپشن‌ها از منابع عمومی و شخصی.
- فیلتر کردن کانفیگ‌های خاموش (TCP Connectivity Test).
- ثبت خودکار و مجدد اکانت Cloudflare WARP با تولید کلیدهای X25519.
- استخراج خودکار کانفیگ‌های Cloudflare Worker از داخل ساب‌اسکریپشن‌ها.

### ۴. داشبورد تحت وب و مانیتورینگ
- رابط کاربری واکنش‌گرا (با فایل `index.html`).
- پایش زنده (Real-time) لاگ‌ها و وضعیت شبکه از طریق WebSocket.
- ذخیره‌سازی تاریخچه رویدادها و لاگ‌ها در دیتابیس SQLite محلی.

## 🧠 موتور تصمیم‌گیری (Decision Engine)

این موتور بر اساس خروجی تست‌های شبکه، اقدامات زیر را انجام می‌دهد:
1. **شبکه سالم است؟** توقف موتور دور زدن و قطع پروکسی سیستم.
2. **Captive Portal؟** اطلاع به کاربر برای لاگین در مرورگر.
3. **قطعی بین‌الملل؟** اعلام قطعی کامل و تلاش با تکنیک‌های غیر متعارف (Tor/Psiphon).
4. **DNS قطع/هیجک شده؟** تغییر خودکار DNS سیستم به بهترین DNSهای اسکن شده.
5. **DPI تهاجمی (SNI Block)؟** اولویت دادن به VLESS-Reality، NaiveProxy، فرگمنتیشن یا ترکیب پروکسی‌ها (Chaining).
6. **UDP مسدود است؟** استفاده از پروتکل‌های مبتنی بر TCP و حذف Hysteria/TUIC/WARP از لیست آزمایش‌ها.

## 🏗️ معماری و ساختار پروژه

پروژه از ماژول‌های مستقل اما به هم پیوسته تشکیل شده است:

| فایل | وظیفه |
| :--- | :--- |
| **`BypssEng.py`** | هسته اصلی موتور. شامل تست‌های شبکه، منطق تصمیم‌گیری، تولید کانفیگهای Xray/Hysteria و مدیریت پردازش‌ها. |
| **`cnfg.py`** | ماژول دریافت کانفیگ. مسئول واکشی ساب‌ها، ثبت خودکار WARP و مدیریت فایل یکپارچه `cnfg.json`. |
| **`run_dashboard.py`** | فایل اجرایی اصلی. وظیفه راه‌اندازی موتور اصلی و سرور وب (Dashboard) را به صورت همزمان (Async) بر عهده دارد. |
| **`api_server.py`** | سرور وب مبتنی بر `aiohttp`. ارائه REST API و WebSocket برای ارتباط با رابط کاربری. |
| **`telemetry.py`** | مدیر دیتابیس. ذخیره لاگ‌ها و رویدادهای شبکه در دیتابیس `SQLite` محلی. |
| **`index.html`** | رابط کاربری تک‌صفحه‌ای برای نمایش زنده وضعیت شبکه، لاگ‌ها و کانفیگ‌ها. |

## 🔌 پروتکل‌ها و تکنیک‌های پشتیبانی شده

- **پروتکل‌های پروکسی:** VLESS (Reality, WS, gRPC, TCP), VMess, Trojan, Shadowsocks (SS), ShadowTLS.
- **پروتکل‌های UDP-based:** Hysteria2, TUIC.
- **شبکه‌های غیرمتمرکز/محیر:** Tor (Direct, Snowflake, obfs4/Lyrebird), Psiphon, DNSTT (DNS Tunneling).
- **شبکه‌های اختصاصی:** Cloudflare WARP و WARP-WS (Workers).
- **تکنیک‌های ضد DPI:** XTLS-Vision, uTLS (Fingerprint Imitation), TCP Fragmentation, Mux.

## ⚡ پیش‌نیازها و نصب

### ۱. پیش‌نیازهای سیستمی
- پایتون نسخه 3.8 به بالا
- دسترسی ادمین (Administrator/Root) برای تغییر DNS سیستمی. *(پروکسی محلی بدون ادمین هم کار می‌کند)*.

### ۲. باینری‌های مورد نیاز (Core Binaries)
برای عملکرد کامل موتور، باید باینری‌های زیر را دانلود کرده و در پوشه `Core` قرار دهید:
- `xray` (یا `xray.exe`)
- `hysteria`
- `tor`
- `tuic`
- `naive`
- `snowflake-client` (یا `lyrebird`)
- `psiphon-tunnel-core` (اختیاری)
- `dnstt-client` (اختیاری)

### ۳. نصب پکیج‌های پایتون
پکیج‌های مورد نیاز را با استفاده از فایل `requirements.txt` نصب کنید:
```bash
pip install -r requirements.txt
```
*(پکیج‌ها شامل: `aiohttp`, `aiodns`, `cryptography`, `aiosqlite` می‌باشند).*

## 🚀 نحوه اجرا

برای اجرای نرم‌افزار (موتور + داشبورد)، کافیست فایل اصلی را با دسترسی ادمین اجرا کنید:

**در ویندوز:**
```cmd
python run_dashboard.py
```
*(حتماً Command Prompt یا PowerShell را با گزینه Run as Administrator باز کنید)*

پس از اجرا، داشبورد به صورت خودکار در مرورگر پیش‌فرض شما در آدرس `http://127.0.0.1:8080` باز خواهد شد. در ترمینال نیز لاگ‌های لحظه‌ای موتور نمایش داده می‌شود. (جهت اجرا بدون رابط‌کاربری، می‌توان به‌صورت مستقیم فایل BypssEng.py را اجرا کرد)

حالت فقط تشخیص (Diagnose-Only):
اگر می‌خواهید برنامه فقط شبکه را آنالیز کرده و گزارش بدهد، بدون اینکه پروکسی یا DNS سیستم را تغییر دهد، می‌توانید آن را با فلگ --diagnose-only اجرا کنید:
```cmd
python run_dashboard.py --diagnose-only
```

## 🛡️ ایمنی و بازیافت سیستم (Safety & Recovery)

یکی از نگرانی‌های کاربران در استفاده از ابزارهای تغییر شبکه، باقی ماندن تنظیمات مخرب در سیستم (Proxy یا DNS) پس از بستن ناگهانی برنامه است.
BypssEng با استفاده از مکانیزم‌های زیر ایمنی سیستم شما را تضمین می‌کند:
- **State Management:** بکاپ گرفتن از DNS و Proxy سیستمی پیش از هرگونه تغییر.
- **Signal Handlers:** تشخیص بسته شدن برنامه (Ctrl+C یا Kill) و بازگردانی فوری تنظیمات.
- **Atexit Hook:** اجرای تابع پاکسازی در زمان خروج نرمال برنامه.
- اگر برنامه به هر دلیلی کرش کند، در اجرای بعدی به صورت هوشمند متوجه تغییرات بی‌جا شده و سیستم را به حالت اولیه برمی‌گرداند.
